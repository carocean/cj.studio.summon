# 菜品语音：真实离线转写到按需呈现

## 实现边界

`DishHearingTurn` 是受信本地宿主回合，复用现有 `PerceptionSceneBridge`、`PerceptionService`、感知授权与事件有效期。它只接收本次预录WAV，不接受客户端提供的“可信转写”或识别回执。没有新增HTTP端点、默认按钮、麦克风权限或自动开始采集。

宿主先 `narrator.pauseForInput`，等待真实适配器停止屏障及宿主确认，将同菜保留为awaiting-input；此时不生成说明。然后才调用现有ASR。因为输入是预录/合成音频，这只证明停声后进行识别，不证明录音发生在停声之后，也不是全双工或真实barge-in。

## 理解与呈现

当前“理解”明确是有限整句规则，非LLM：
- 解释一下这道菜
- 介绍一下这道菜
- 这是什么菜
- 这道菜是什么

只规范空格与末尾一个标点，不做模糊纠错或子串匹配。否定、引用、多意图、未知句子不执行。没有通用语义理解或识别准确率承诺。

有效转写只能从桥接器自身最新、未消费、真实处理标记的hearing observation取得，消费前再次检查感知权限、creature generation、事件有效期与context。消费后立即清除，旧事件不可用于下一回合。回合在停声前后、ASR前后及提交前校验同session/task/dish/catalog/revision/context。符合规则后才由宿主生成当前菜的说明视图，继续使用已有Flutter保护传输、合成插画与缩放。

## 取消和失败

close幂等并绑定桥接owner；旧回合不能取消或解锁新回合。narrator退休失败保留所有权。close请求取消感知服务，服务在capabilities等待返回后、处理返回后复验取消generation，防止取消后才启动ASR。即使适配器忽略取消，迟到结果也不呈现。不会自动重放识别、恢复播放或重新开麦。

未知识别保持已停止的当前菜，不生成业务界面。原始语音不持久保存；新增转写缓存有时间上限，消费/替换/取消/关闭均清除。继承现有metadata-only感知记录规则。明确返回的转写用于本次宿主反馈，不是隐式写入聊天历史。

## 实测事实与限制

使用已有离线中文TTS生成“这是什么菜？”，现有Vosk实际转写为“这 是 什么 菜”，有限规则命中，同菜details生成。真实Flutter widget通过临时TLS登录、cookie/CSRF、保护代理与SQLite读取该结果，显示说明、合成插画并放大至125%，真实读回一致。

先尝试“解释一下这道菜。”时，Vosk识别为“你 试 一下 这 道 菜”；系统返回unrecognized，未生成说明。没有把错听句加入允许规则来伪造成功。该差异证明当前模型存在明显识别局限；不应宣称任意用户表达均可理解。

实际TTS/ASR均本机离线，输入为合成测试语音；播放器仍是受控适配器，图片为本地合成插画。没有真实用户录音、声卡播放、手机真机、真实浏览器cookie行为或跨设备验证。普通应用的自动需求识别入口、LLM推理与真实麦克风交互尚未接入；本阶段交付的是可重复验证的宿主链与按需呈现接线。

## 本轮验证

开启已有离线模型的最终Node全量461项：453通过、8跳过、0失败；11项新hearing测试含实际TTS→ASR。Flutter全量361通过、2跳过、0失败，静态分析无问题，真实ASR模式的菜品TLS界面验收包含其中。本轮未改Flutter生产代码，未将旧Web构建结果重复称为本轮新构建。

独立审查推动修复并回归：旧回合close幂等和owner归属；退休失败不释放；capabilities等待中的取消代际；停声前捕获creature generation，防止停声期间撤权再授予让旧音频越过授权边界。终审确认这些问题闭合。
