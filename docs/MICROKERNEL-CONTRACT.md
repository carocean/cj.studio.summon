# 微内核最小契约 r1：委托、数据、执行与事实

**设计修订，尚未实现。** 本文将 [统一设计](MICROKERNEL-DESIGN.md) 的不变量收敛为可做确定性测试的契约。与旧设计概述冲突时，以本契约为准；不是现有 v0.17 Kernel 的能力声明。先完成独立复审，再实现纯契约内核，不增加业务功能。

## 0. 首版范围和信任边界

首版单写入域、单持久事务存储；不承诺多地域一致性或外部 exactly-once。所有身份来自可信接入，不从请求字段自报owner。模型、传感器内容、业务正文和生成场景均不签发权限。适配器注册是管理操作，不是LLM选择。

内核只解释有限、可判定的约束：稳定ID相等/集合包含、规范资源ID的已注册范围包含、效果集合包含、用途ID相等/集合包含、接收主体ID集合包含、期限、次数/金额/字节预算和版本。地理计算/人格/语义不在内核解释。未知用途或无法证明的范围包含关系一律拒绝，不让模型给出“约束等价”的结论。

持久适配器必须提供串行化事务、CAS、唯一约束和提交后可恢复保证，外部发出前须完成要求的持久提交。首版可以使用一个受测的本地事务存储；旧JSON快照不据此升级为断电保证。执行器必须经受控读取/网络出口取数据和执行许可；若一个插件能绕过出口自由读文件或联网，本契约无法保证数据流限制，不能将它作为可信执行器启用。

## 1. 核心记录与不可变引用

可变对象使用 `revision` CAS，签发/引用清单使用规范化字节摘要。摘要只证明内容身份，不证明内容可信。每个记录含 `id、tenant/authorityDomain、createdBy、createdAt、revision`；时间策略使用本域受测时钟，已观察过期持久锁存，回拨不复活旧租约。

| 记录 | 最小内容 | 谁能改变 |
|---|---|---|
| Principal/Resource | 稳定身份、控制者、类型化资源引用、生命周期、版本 | 有该管理能力的主体 |
| Grant | 根委托者、签发者、被委托者、父Grant、动作/数据范围、用途、接收方、预算片、期限、授权世代 | 新授权/撤销，不原地扩大旧Grant |
| Evidence | 来源身份、通道、来源/归因等级、因果ID、内容引用及标签、观测时间 | 追加证据；不能重写原证据 |
| Activity | 原始意图身份、发起主体、服务清单摘要、输入/效果摘要、约束、委托链、状态、尝试引用 | 经状态机与CAS |
| Permit/Attempt | 唯一许可、活动/尝试/执行者、fence、预算保留、绑定摘要、期限和消费状态 | 受控派发门 |
| Receipt | 活动/尝试/效果ID、证据等级、发证者、来源消息ID、结果引用/标签、可信验证状态 | 追加与核对，不能覆盖事实 |

生物、人格引用、关系、情境、场景及设备承载首先是受保护Resource，不另开一套权限/任务系统。Resource类型只是约束模式，不把人物、布局、地图算法塞进内核。Grant、活动和事实生命周期不能因为呈现Resource被收起就消失。

## 2. 跨Agent委托：只能衰减，不得拼接扩权

Grant最小格式：

```text
Grant {
  id, rootPrincipal, issuer, delegate, parentId?,
  operations, resources, effects, purposes, recipients,
  budgetSlice {poolId, reservationId, units},
  notBefore, expiresAt, maxDelegationDepth,
  authorityEpochs, evidenceRefs, state
}
```

- 每个子Grant的签发者必须是父Grant的被委托者，根委托者保持不变，链无环、深度首版最多8。执行者与数据接收者分别记录：帮忙推理的模型/服务也是接收方，不等于最终用户。
- 子动作/资源/效果/用途/接收方必须是父集合子集；期限不能延长；可委托深度递减。子预算必须从父预算池原子切出/保留，两个子分支不能各复制一份完整预算。回收未用片需记录释放，已消费不能退回为可重复消费额度。
- **单条链证明一次权限**。不能拿Grant A的读取权限和Grant B的发布权限拼成未经批准的“读后发布”。有多个数据来源时，每一来源都必须通过同一目标用途/接收方的数据门；拥有发布动作权不代表拥有输入数据披露权。
- 服务组合只引用各步骤的合法衰减链，不为组合创建隐式超集权限。每步记录 `rootPrincipal → agents/services → executor → recipients`；跨所有者协作需要各数据控制者相应授权，不把活动所有者当所有数据所有者。多个控制者的独立授权可以作为必须全部满足的合取条件，但不能取并集来填补任何一条链缺失的权力。接收方若为已注册群体，成员范围/历史可见策略也必须绑定版本，不能用稳定群ID掩盖新增接收者。
- 任一祖先撤销/期限到达使全部后继不可再消费。派发/读取/披露校验全链当前世代；单看叶子有效不够。新授权产生新ID，不能让旧排队许可复活。
- 第一版不自动合并Grant，不做语义用途推理。确需增加权限时回到明确授权来源签发新根/新范围，而不是由Agent自批准。

反例：个人伙伴允许工作Agent整理日程，不代表工作Agent可让餐馆看到日程；业务服务获得下单权限也不能用另一个代理的联系人读取权附带营销。

## 3. 派生数据与输出披露门

### 3.1 数据标签不是“摘要后就公开”

每个输入及派生Artifact记录：`sourceRefs@versions、controllers、allowedPurposes、allowedRecipients、retentionDeadline、originGrantEpochs、classification`。摘要、嵌入、画像、场景标题/预览、模型上下文和缓存都是派生数据，默认继承所有来源约束：用途/接收方取交集，保留截止取最早，分类不降低，来源集合取并集。

内核从执行器实际获准读取的资源集合和完整执行上下文依赖闭包生成来源，不接受模型自报“没有敏感来源”。仅本次attempt读集合不够：长期Agent、模型历史、持久记忆、工具缓存和先前派生状态都可能影响输出，必须按第3.4节登记为输入；无受控信息流或带未登记隐藏状态的旧插件不能被当成已证明安全。输出数据是否真的脱敏不是内核能从文字证明的事实，首版**不支持自动降密**。需要降密时必须是来源控制者明确授权的独立转换契约及可信执行器，不是LLM判断。

### 3.2 每次披露都是独立检查

`authorizeDisclosure(artifactId, recipientId, purposeId, channel, expectedEpochs)` 检查全来源有效性、控制者限制、委托链、接收方、用途、渠道及当前设备承载身份，返回短期、限定字节/读取次数的句柄。以下都过此门：发给另一个Agent、模型请求、渲染到个人/共享屏、播放音频、日志/遥测、跨端缓存。数据落到UI组件不免检，服务成功也不等于能公开其结果。

- 禁止以“服务返回给用户”为默认通行证。真实猫代理的位置、真人位置、公开头像、语音通话入口必须使用不同数据资源和披露授权。
- 模型/第三方接收者未获准时，生成请求在外发前失败；可选择本地允许方案，但不偷换接收者或用途。
- 关系成员加入情境，只能看到授权范围内的新/历史数据，不能自然获取完整情境日志。

### 3.3 撤权和缓存

撤销增加来源世代，立即阻止新读取、派发和披露；关联派生数据进入 `stale/quarantined`，系统托管缓存失效、待发预览撤回、设备读取租约撤销。重新生成须重新授权，不能仅改输出标签。保留的事实审计仅存最小必要引用/摘要和受保护载荷，不用于推荐或模型记忆。

已交付给第三方的内容不可承诺远程“收回”；离线设备只可在短租约有效期内使用受保护缓存，无法联网核验时过期关闭敏感呈现。用户删除、证据保留和法定义务需独立政策，不以审计为名无限保留原媒体。首版无远端强制删除保证，必须在交付状态中记录已披露对象及撤回请求/结果。首版披露只支持有上限的缓冲载荷，发送前再次消费披露句柄；已经越过出口的字节不可撤回。流式播放/传输必须另定分片重校验与已排队字节边界，未定义前不得宣称流式实时撤权。

### 3.4 跨attempt状态：显式上下文，或可验证隔离

定义不可变版本的 `ExecutionContextRef`，不是新的权限系统，而是受保护Resource。其清单含 `executorProfile、contextVersion、stateRefs、sourceClosure、grantEpochs、isolationMode、rebuildEvidenceRef`。stateRefs至少覆盖会影响输出的模型会话/线程历史、系统注入记忆、持久Agent状态、检索结果缓存、工具缓存、先前生成摘要/嵌入，以及共享worker残留。仅列本轮发送的prompt不够。

每次prepare绑定该上下文摘要，并检查所有状态来源的用途、接收方、期限与当前授权；输出标签来源为 **本次实际读集合 ∪ 已绑定上下文完整依赖闭包**。首版在prepare冻结输入/上下文，不能运行中增加会影响输出的未登记状态；工具回传或新记忆须成为后续生成活动的显式输入，重新绑定和授权，不悄悄扩展旧许可，也不能借此变更外部业务效果而冒称同一次安全重试。上下文的新版本同样继承本次输出/状态的来源限制；裁剪可见历史、改名字、摘要或换模型不会自动降密。

首版只允许两种路径：

1. **显式持续上下文**：所有可影响结果的状态可枚举并通过受控句柄提供，来源标签保守合并。来源撤权、用途/接收方不符使整个相关上下文stale/quarantined，禁止用于低权限新尝试。不能只删原始文档而保留无标签摘要继续推理。先前派生物依赖闭包不能被新公开输入覆盖。
2. **经过验证的新隔离上下文**：由受测执行器配置创建无可访问旧状态的worker/会话，只注入重新获准的输入；禁用共享未登记缓存、旧会话ID、未授权文件/网络状态。结束时销毁或封存为带标签的显式上下文。重建证据记录隔离配置、输入摘要与旧句柄不可达性，而不是让模型声称已经忘记。若重建材料来自私密摘要，仍继承其标签，并不因为worker是新的就公开。

执行器配置必须声明能否满足上述路径，内核只允许已验证的配置处理对应数据。适配器无法枚举或隔离隐藏状态时，标记 `context_provenance_unknown` 并拒绝受此保证覆盖的生成/共享输出，不以“相信它没泄漏”补成空来源。第三方模型可能保留服务端历史、缓存或其他未知状态：**一次新的API请求、session ID变更或forget提示不等于遗忘**。无法验证的外部保证必须明示，首版确定性原型不依赖它；已有实验CompatibleProvider不能据本契约升级为已证明信息流隔离。

依赖闭包使用不可变资源版本的有向无环引用，循环、缺失来源或超出受测资源上限均拒绝，不截断后标为干净。上下文存储和可读权本身也受标签约束；审计只保留必要身份/摘要，不在日志复制私密会话。

## 4. 服务契约与执行许可

### 4.1 服务清单先确定效果与成功标准

不可变 `ServiceContract@digest` 包含：输入/输出模式、明确的动作/数据效果、接收方角色、参数上限、可信执行器集合、预算计量、幂等协议、取消/查询协议、证据签发者与 `successCriterionId`。成功判据由受信任部署注册的有限验证器实现，不是服务调用者或模型临时给一段代码。

首版至少声明三种外部能力档：

- `idempotent-queryable`：接收端持久支持稳定效果键+输入摘要，重复请求返回同一效果，并能查询。
- `fenced-queryable`：接收端支持隔离令牌，拒绝旧fence，并能查询；若同一效果还可能重复，仍须效果键协议，fence单独不等于幂等。
- `no-safe-retry`：不能证明上述性质。请求可能已发出后禁止自动重新执行，进入uncertain，由查询/人工核对解决；首颗内核不启用此类现实写操作。

### 4.2 Permit绑定完整，不是一个布尔allowed

```text
ExecutionPermit {
  id, activityId, attemptId, executorPrincipal,
  serviceDigest, inputDigest, executionContextDigest, effectDigest, effectId,
  recipientsDigest, purposeId, delegationChainDigest,
  budgetReservationId, maximumUnits,
  authorityEpochs, policyRevisionRefs, evidenceRevisionRefs,
  fence {domain, counter}, notBefore, expiresAt,
  status: issued | consumed | revoked | expired
}
```

改变输入、执行上下文、版本、效果、接收方或用途就不能复用旧Permit。`effectId`在一次已授权业务活动内稳定，跨重试不变；`attemptId`每次尝试唯一。不同用户真的发出第二个需求使用新活动/效果ID，不能按内容相同去重。首版Permit仅可信执行门可消费，普通Agent拿到序列化字段不代表持有权限。

### 4.3 派发线性化与消费

1. `prepareDispatch(activityId, expectedRevision)`：事务内复核全委托链、输入标签/披露、边界/地理政策/连接、用户约束和预算；原子保留预算，分配新尝试与持久单调fence，记录issued Permit。每个Activity只有一个active dispatch slot，由事务唯一约束保护，而不仅依赖请求CAS。已有issued或consumed尝试时不得再次prepare，即使调用者读到了新revision。仅当前尝试已终结、过期且证实未消费，或已进入uncertain且契约证明可安全重试时，才能显式replaceAttempt；替换先原子退休旧slot/许可，再增fence，旧许可不可再消费，effectId保持。暂停/取消/撤销已存在时不签发。
2. `consumeForDispatch(permitId, executor, expectedFence)`：受控出口在最后发送前再次核验当前状态、期限、全世代及绑定摘要；在同一事务内将issued→consumed、记录派发意图/出站记录。重复消费只返回历史ack/状态，不返回另一份send capability。出站记录只能由唯一发送门持有的当前slot推进；不能把命令重放的成功响应作为重新发送的依据。**这个提交是本域派发线性化点，不是外部业务完成点。**
3. 消费成功后仅指定执行器可用规定输入/接收方发送。内核崩溃若无法确定网络发送是否发生，恢复为uncertain，不能因“没有响应”重新消费。只有服务契约证明安全时才创建新attempt，用相同effectId、相同effectDigest查询或重发；不可换新effectId规避去重。
4. 预算按契约保留/结算，unknown成本保持保留/待核对，不因超时直接退款再消费。外部真实金额发生与本地预留不同，记入事实回执后核对，不伪造账单结算。

### 4.4 Fencing及无法保证的边界

持久fence由内核域分配，不能回拨或重用。受控出口及支持此协议的接收端拒绝低于当前fence的执行；旧worker不能在重新派发后凭旧Permit再次发出动作。仅本地检查无法阻止一个已越过出口的旧包稍后被不支持fencing的远端处理。

所以首版保证是“未消费不派发；重复本地消费不二次授权；支持协议的接收端拒绝旧执行；不支持时保守uncertain”，**不是**“撤权一瞬间可以原子撤回所有外部动作”。消费后取消与远端动作存在竞争，必须记录取消意图和真实结果。网络断开后的补偿是新活动，需要独立契约/授权，不能把“取消”自动翻译为退款或反向操作。

## 5. 回执不是一个completed字符串

每条回执绑定 `receiptId、activityId、attemptId、effectId、serviceDigest、evidenceKind、issuer、issuerMessageId、observedAt、payloadRef/labels、verification`。内核按签发者+消息ID去重；相同ID不同内容视为冲突证据而非覆盖。过期/撤权不允许继续行动，但可信迟到证据仍可进入受保护事实账本。

| 证据等级 | 能证明什么 | 不证明什么 |
|---|---|---|
| dispatch_recorded | 本域出口记录了派发意图/发送情况 | 对方收到、业务完成 |
| provider_accepted | 注册接收端确认接收指定效果请求 | 下单/付款/开机一定成功 |
| completion_claimed | 契约允许的业务签发者声明效果完成 | 声明一定等同物理观测；非授权签发者声明不算 |
| observation_confirmed | 注册观测源以规定关联证据确认结果 | 其他未测条件或所有人都看到了结果 |

没有统一要求每项服务都必须有独立传感器：只读API可把经验证的响应当其约定成功标准；订单可能以商户签发订单ID为完成证据；空调启动可以要求控制回执+设备状态观测。内核只有在**清单事先指定的成功判据、可信签发者、效果关联及证据组合**成立时，才设置业务结果 `succeeded`；不能把HTTP200或模型说“好了”通用化为成功。

证据可冲突：返回200但设备显示未启动，保留两份事实并标记 `disputed/uncertain` 供核对，不以最后一条简单覆盖。没有达到判据则保持accepted/pending/uncertain，不生成完成呈现。向用户展示哪一级证据也过数据披露门。

## 6. 控制意图、执行事实、结果交付分别记录

```text
IntentState: proposed → authorized → queued → cancel_requested | cancelled | suspended | active
ExecutionState: not_dispatched → dispatch_recorded → accepted →
                claimed_complete → confirmed_success | confirmed_failure | uncertain | disputed
```

这不是要求每项业务必经每个中间态；服务成功判据决定哪些证据充分。`IntentState`记录用户希望怎样，`ExecutionState`是事实派生视图，不能互相覆盖。另按接收方/承载租约保留简单的 `DeliveryState: not_authorized | pending | handed_to_transport | device_acknowledged | expired | revoked | unknown`；设备ACK也不证明人已看见/听见。它是回执派生字段，不需第三套独立工作流。业务完成、结果可披露和结果已交付三者不可互相替代。

- 消费前取消：同事务撤销未用Permit/预算保留，确认事实为not_dispatched后置IntentState=cancelled，才能报告“未执行并已取消”。cancelled是该意图的终态，普通prepare/resume和旧commandId重放不能恢复；用户重新要求工作须创建新的明确意图/活动及相应授权。
- 消费后取消：记录cancel_requested；若支持取消则经另一个受控尝试请求取消，不能先显示取消成功。远端已完成仍记真实完成，可同时显示“取消请求未阻止已发生动作”。
- 迟到完成：登记事实，不恢复旧用户意图，不再次派发，不自动披露给已撤权的第三方。
- 与数据删除冲突的载荷：按最小事实账本和保留政策处理；删除正文不抹去“效果可能发生”的状态依据。

## 7. 最小性：删除/外置反例表

“产品必需”与“必须在受信任核内”分开。下表是首版取舍，不宣称数学上唯一最小实现。

| 机制 | 删除或完全交给普通Agent的最短失败反例 | 核内最小部分 | 外置部分 |
|---|---|---|---|
| 身份/受保护资源版本 | 切模型产生新伙伴；伪造owner读另一生物记忆 | 稳定ID、控制者、引用/CAS与访问门 | 个性、记忆语义、关系解释 |
| 委托衰减/数据标签 | 工作Agent把日程摘要交给餐馆，组合两授权扩权 | 链包含检查、来源约束、读取/披露门 | 目的解释、摘要/嵌入生成 |
| 因果/原意图ID | 语音响应丢失重试成第二次下单 | 因果ID、去重约束、证据来源 | 意图识别与情境推断 |
| Permit/预算/fence | 旧worker恢复与新worker双执行；各子Agent复制预算 | 原子保留、绑定许可、单次消费、fence | 业务执行、可达性计算 |
| 事实账本/成功判据 | accepted被说成开机成功；撤权擦掉已付款事实 | 证据认证/去重、注册判据执行、双状态 | 商户/传感器发证、业务核对 |
| 有界租约/活动恢复 | UI关闭误取消任务；失效设备继续展示隐私 | 资源租约、撤销、状态恢复、配额计数 | 设备连接、场景布局和切换策略 |
| 人格/关系模型 | 外置不会破坏以上边界，只要引用和读写受保护 | **不内置推理模型** | 必备生物运行时 |
| 地理索引/传播算法 | 算法可替换；绕过核内方向策略才会扩权 | 角色方向、范围策略版本、证据资格核验 | 必备GeoOS空间/区域治理服务 |
| 生成UI/服务方案 | 生成器替换不应影响权限/事实；无核内eval必要 | 清单引用、生成任务授权、交付门 | 必备情境/生成/呈现服务 |

系统首次可用必须包括生物运行时、GeoOS和情境服务的最小适配，而不把它们变成随意可选插件。但“随系统提供”不意味着与内核有同样的权力。

## 8. 人格连续性的三层验收

1. **内核层**：身份、personaRef版本、关系资源/记忆命名空间与授权跨重启/设备/模型保持；未经授权不能改写或混读。可以做确定性测试。
2. **系统服务层**：生物运行时检索正确记忆，版本化偏好、习惯和表达策略；工作/休闲Agent的关系与上下文不串线，用户纠正可追溯。用受控场景和模型适配测试，不把prompt持久化当全部完成。
3. **产品层**：用户能感到仍是同一个伙伴，个性表现自然且可纠正、不虚构能力，不因模型更换失去重要约定。这需要真实交互评价，不能由ID不变或单元测试证明，也不是意识证明。

## 10. 下一步门槛

先独立复审本契约的委托、数据流、消费竞态和证据状态。通过后只实现一个单域、确定性内核测试模块与模拟执行器，逐项实现D/L/X/R/G/B/P测试；未通过之前不接真实写操作，不新增业务页面。选择存储、编码摘要格式和具体签名/认证机制时再形成小型ADR，不能留下实现者自行猜测的安全语义。未实现的协议不以现有68项实验测试替代。

### r1命令结果与预算补充

首版命令均以可信接入身份和 `commandId` 开始，变更须带 `expectedRevision`。同调用者/同commandId/同规范请求摘要重放只返回既有结果的历史ack/资源引用；相同ID不同摘要返回conflict，不重新执行。尤其consumeForDispatch的成功重放不返回可再次触发发送的权力；唯一出站记录及其slot状态是执行依据，而不是调用结果文字。首次拒绝不产生出站请求；是否保留拒绝证据由固定最小审计策略决定，不能保存未经授权的原文。

| 命令 | 事务/输出边界 | 稳定拒绝类别 |
|---|---|---|
| attenuateGrant(parent, childSpec) | 原子保留子预算、生成子Grant及父子关系 | delegation_denied / scope_not_subset / budget_exhausted / revoked |
| registerDerived(attempt, outputs) | 从受控读集合∪执行上下文闭包自动附依赖/标签，生成不可变Artifact引用 | provenance_missing / attempt_mismatch / source_revoked |
| authorizeDisclosure(artifact, recipient, purpose, channel) | 签发短期读取/传送句柄；实际消费时再核世代 | purpose_denied / recipient_denied / stale_source / lease_expired |
| prepareDispatch(activity) | 同事务创建attempt+预算保留+issued Permit | revision_conflict / active_attempt_exists / boundary_denied / unavailable / budget_exhausted |
| consumeForDispatch(permit) | CAS issued→consumed，并持久记录派发意图 | consumed / stale_fence / binding_mismatch / revoked / expired |
| registerReceipt(envelope) | 原始事实追加/去重；判据视图更新与披露分开 | issuer_untrusted / effect_mismatch / duplicate_conflict |
| requestCancel(activity) | 更新意图、撤销未消费许可；不改写执行事实 | revision_conflict / not_authorized |

预算是带单位的非负整数向量，例如请求次数、字节数、模型token上限、某货币最小单位；不同单位/货币不相加、不自动换算。父池先保留，再向子分配可消费片；取消未消费许可可释放，已消费/结果不明的成本保持待结算，防止重复退款式扩权。计量结果不能超过许可上限后仍自动继续；超额执行器视为契约违约并阻断后续工作，已发生费用作为事实核对而非伪称未发生。

首版fence域为 `(authorityDomain, activityId)`，不同活动不因共用执行器而意外互相淘汰。此域不自动串行化两个不同活动对同一设备/订单的冲突操作；需要资源级互斥/业务冲突策略才能启用该类并发现实写入，首版不承诺该能力。每次有效重派增加该域counter；远端协议必须携带相同命名空间、effectId、输入/效果摘要和fence才能声称支持旧尝试隔离。额度公平策略可外置，但内核的保留/消费与拒绝不可绕过。首版只承诺单域预算，不把它称作分布式限流。

## 11. 实现前必须通过的四份ADR

以下是进入代码阶段的门槛，不是已完成决定：

1. **规范编码与摘要**：字段模式、未知/重复字段拒绝、整数/单位范围、字符串规范化选择、清单/输入/上下文摘要算法及版本。相同字节身份和语义身份如何比较必须确定，不能靠各适配器各算各的。
2. **单域事务与崩溃点**：具体存储及durability配置，Grant预算切片、slot/Permit消费、command重放、outbox与Receipt的原子边界；在提交前/后、发送前/后、回执前/后逐个注入崩溃，定义恢复为未派发或uncertain的依据。
3. **主体/执行器/回执认证**：可信接入与管理签发者、认证材料保管、撤销世代、执行器配置准入、回执签发者与成功验证器注册；不能让业务请求自报可信issuer。模型/传感器内容保持不可信。
4. **实际字节出口的唯一所有者与恢复**：谁持有发送权，worker如何只能提交受限请求而不能绕过门，单活动slot怎样防两发送者，何时消费披露/执行许可，崩溃后如何避免旧worker继续发送；受控缓冲与已越界字节的保证范围。跨attempt上下文的隔离/清空/显式注入也须在这一执行器准入设计中可验证。

限定首个实现：单写域、确定性适配器、可验证显式上下文或隔离worker、有上限的缓冲载荷、模拟执行与回执；无真实业务写动作、无未知第三方持久上下文。通过这些ADR和L3–L5反例后，再考虑把真实适配器逐一接回，不能从68项旧实验测试推断新协议已经实现。
