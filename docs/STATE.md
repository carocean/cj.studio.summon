## 2026-11-17 · v0.4.0 统一持久主体与服务运行

生产 Runtime、ServiceScheduler 与 Kernel 现在共享主体、能力和会话，不再使用静态聊天主体注册。新建主体直接出现在 `/v1/creatures`；模板只首次引导，不在重启恢复撤销权限。会话写入磁盘；异步模型返回时再次检查生命周期与挂载权限，并以回合版本防止并发覆盖。

验证：`npm test` 21 项全部通过。新增 5 项针对所有者/模板幂等、动态主体发现及会话恢复、飞行中撤权、两个运行适配器的冲突、v0.3 格式兼容。真实子进程测试扩展为创建自定义主体、挂载对话、通过旧 API 交流、后台自动任务、停止重启后主体/任务/会话均恢复。

Flutter 未编译，真实 LLM 未联调；仍是单开发令牌及本地服务。后台任务只运行 local.report；会话按 ID 恢复已实现，但手机端自动恢复尚未实现。不要把 mock 模型、模拟空间当成真实智能和地理验证。

下一步：Flutter 官方 SDK 和 UI 可运行验收，提供统一主体/能力/任务界面；另需完善连接状态模型与受约束的计划执行协议。
