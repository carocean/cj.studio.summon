# ADR 0001：首版规范编码、摘要及不可变快照

状态：限定原型采用，待实现测试验证。适用单域确定性微内核，不改变旧API。

## 决定

采用自定义且版本化的 **C1 JSON子集**，不声称完整RFC JCS实现。首版内核只接可信接入转换后的值，不开放HTTP/任意JSON文本入口。

- 允许null、boolean、整数（绝对值≤Number.MAX_SAFE_INTEGER，拒绝-0）、Unicode标量字符串、稠密数组、普通数据对象。拒绝浮点/非有限数、BigInt、undefined、函数、Symbol、Date、Buffer、稀疏数组、循环、访问器、自定义原型、Proxy和不可枚举/符号属性。
- 对象键为ASCII `[A-Za-z][A-Za-z0-9_]{0,63}`，禁止constructor/prototype；键按ASCII升序。字符串保留原Unicode，不隐式NFC转换，拒绝孤立代理项。身份/类型/用途等协议ID另限制为ASCII稳定ID，不用自然语言同义词做权限比较。
- JSON无空白，字符串采用JSON转义；数组保持顺序。模式声明为集合的字段由对应模式验证器要求排序且无重复，不能把所有数组一律重排。
- 上限：深度32、每数组/对象最多256项、每字符串最多16384 UTF-8字节、完整记录最多65536 UTF-8字节。超限拒绝，不截断。
- 摘要：`SHA-256(UTF8("cj.summon.c1\0" + recordKind + "\0") || canonicalBytes)`。recordKind必须为固定注册种类，清单、输入、上下文、命令不能跨种类复用摘要；输出形式 `sha256:<64 lowercase hex>`。
- 身份不同但规范字节相同不代表授权相同；摘要不能替代资源ID、控制者、版本或认证。

## 快照与重放

接入立即验证并编码，再从规范字节建立独立副本；存储的是不可变规范字节及摘要。prepare读取已保存版本，不能继续引用调用者可变JS对象。执行器取得由受控运行环境封装的副本，输出标签使用已绑定来源闭包。冻结对象是防误改辅助，不是对恶意同进程插件的沙箱。

同调用者+commandId存规范命令摘要和历史ack；相同内容重放返回ack，异内容冲突。派发重放永不发第二次字节。以后增加HTTP入口时，须在JSON解码前拒绝重复键并执行同一模式；当前不把JSON.parse静默覆盖重复键视为安全接入。

## 替代方案与后果

不使用任意JSON.stringify（键顺序/数值/访问器歧义）；暂不增加第三方规范化库。C1跨语言兼容需共享测试向量，未来升级用新版本标签，不能用新编码重新解释旧摘要。

## 验收

重排对象键同摘要；数组顺序不同摘要；种类不同摘要；非法数值/原型/访问器/稀疏/循环/超限全部拒绝；修改原对象不改变已保存快照；读取返回对象修改不改变存储；已绑定上下文变化必须新快照及重新授权。
