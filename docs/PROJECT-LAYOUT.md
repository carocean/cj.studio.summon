# 子项目划分：先跑通 Node.js 单机，再按需要演进

用户最新方向：先让微内核与生物/感知/生成场景闭环可用，不先上 ECM，不提前拆成分布式平台。目录边界是职责边界，不意味着现在运行很多微服务。

| 子项目 | 当前职责 | 不应承担 |
|---|---|---|
| `microkernel/` · @cj.studio/summon-microkernel-lab | 编码/不可变版本、身份句柄、Grant与来源闭包、Permit消费、模拟效果证据、单域事务 | 银行字段、宠物表情、ASR算法、页面逻辑 |
| `runtime/` · @cj.studio/summon-runtime | 生物/情境/感知事件编排、按需求构造场景、持久业务任务、受控调用内核；loopback HTTP适配 | 绕过Grant直接调用现实服务；把表单关闭当任务结束 |
| `app/` · Flutter | 听视觉交互与生物呈现、受限场景渲染、明确用户操作、错误/重连恢复 | 自行签发权限、把模型输出当可执行代码或可信回执 |
| `server/` · 既有实验后端 | 已验证的离线ASR/OCR、会话/服务/模型适配实验，保留回归 | 自动继承新微内核保证，或被称为已经完成迁移 |
| `docs/` | 原文/推导/实现边界、契约、决策与可复验步骤 | 用规划代替真实验证 |

当前`runtime`通过仓库内模块导入使用`microkernel`，共享一个可信宿主和core SQLite。模拟sink独立数据库，演练提交后未知事实，不是真实银行。没有网络化内部RPC、服务注册中心、分布式事务或ECM依赖。

后续可替换的边界：感知事件入口（媒体来源/主体/时间/用途）、模型生成器（返回带版本的场景与服务提案）、受限场景协议（稳定字段ID/类型/选项/值/修订）、业务执行器（固定清单/接收方/回执）、呈现终端（显示/收起不控制业务生命周期）。这些边界先在进程内测试清楚；只有资源或部署需求证明必要时，再讨论拆服务及跨域身份/事务语义，不能把函数换成HTTP就宣称分布式安全。

本轮只把一个明确合成业务模式贯通。人物个性是静态说明，情境及感知是显式合成事件，场景构造是确定性模式。它验证“不是默认聊天框”的交互与状态契约，**不证明通用生成能力、真实伙伴智能或真实设备感知**。
