# 生成式操作系统：端到端验收主线

状态：验收设计，不代表新微内核已经接入 Flutter。用户最新方向优先于早期聊天原型。

## 不可被底层工程替代的体验

用户面对的是自己的多个有持续身份、个性和关系的 AI 生物。默认交互是听觉与视觉，不是聊天页，也不是给固定页面增加头像。系统结合获准的现实情境、业务与习惯选择/建议合适生物，按当下需求生成并持续调整服务与场景。用户可以纠正情境或切换生物；此操作不删除未完成任务，不把原生物全部记忆复制给新生物。

麦克风/摄像头只能经明确权限及可见启停采集；权限拒绝时可选择获准媒体等替代入口，不能暗中开启传感器。感知证据、说话者身份与行动授权是三件事。耳朵听到指令不等于已识别有权限的用户。

生成器负责提出具体业务结构和交互，不限于“显示文本框”口令。受限渲染协议是执行安全边界，不是把预制页面选择冒充通用生成。当前确定性实验只能验证协议；真实生成质量、个性、音视觉体验必须另行实测。

## 银行职员场景：只使用合成材料

这是用户提出的应用场景，用于反推系统契约，不是授权执行真实开户。

1. 默认呈现生物及当前服务情境，无常驻聊天输入。通过合成语音/图像证据形成“职员协助客户办理开户”的候选需求。
2. 选择具备该业务能力的工作生物。个人伙伴保持身份与关系，但不向工作生物泄露私人历史。识别不确定时以语音/选择确认业务类型，不默默办理。
3. 工作生物基于已审核业务服务模式，当场提出结构化表单，例如合成客户别名、账户类别、联系偏好。字段包含稳定字段 ID、类型、必填/校验、用途、接收者、敏感等级及服务模式版本。**不采集真实证件、财务信息或客户资料。**
4. 业务变化时生成场景新版本：保留仍适用且仍获准的字段值；删除字段不再出现在提交清单，变化的接收方/用途重新核验。模型不能自造“确认已签字”或默认代选同意。
5. 职员输入的是业务表单，不是把所有内容塞进通用聊天历史。录入先保留为受保护的任务数据；视图只读获准投影。重启恢复和切换生物仍须验证接收约束。
6. 首个实验只允许本地模拟校验及生成草稿摘要，无银行网络、无真实账户、无法律同意、无外部提交。显示“模拟草稿”，不能显示“开户成功”。
7. 表单完成后可收起，回到生物或下一需要的场景。关闭场景不是取消任务；取消任务也不抹去已经发生的事实。需要修改时再生成合适视图。

## 可观测验收矩阵

| 编号 | 系统级验收 | 必须观察的结果 | 责任层 |
|---|---|---|---|
| S1 | 冷启动，已有获准工作情境 | 生物+当下场景，无默认聊天框；情境可纠正 | 情境/伙伴/呈现服务 |
| S2 | 听觉或视觉输入解释业务需求 | 感知来源和可信度保留；未获说话者授权不执行动作 | 感知服务+身份/Grant |
| S3 | 从个人伙伴切换工作生物 | 身份/关系连续；仅显式获准任务材料跨主体 | 伙伴服务+Context闭包 |
| S4 | 开户需求与另一个业务需求 | 字段结构随业务实际变化，不只标题或泛文本框不同 | 生成器+服务模式+渲染器 |
| S5 | 表单更新/迟到生成结果 | schema revision匹配才应用；旧结果不覆盖新输入 | 场景服务+CAS |
| S6 | 私人记忆曾进入生成上下文，后撤权 | 新公开表单不能携带旧缓存/摘要；未知隐藏状态拒绝 | Context+披露门 |
| S7 | 关闭表单、切换生物、重启 | 未完成任务保存；旧视图不持有新执行权 | 持久活动+呈现服务 |
| S8 | 重复提交、消费后崩溃 | 不双执行；显示待核对而非成功/失败猜测 | Permit+回执 |
| S9 | 业务仅返回accepted | 显示已接收，不显示业务完成 | 证据判据 |
| S10 | 地理广播进入工作场景 | 地理可达不自动中断用户；不得偷用个人生成预算 | GeoOS+注意力/预算服务 |

每个测试报告分别标记：合成感知、真实离线处理、真实模型、真实设备、模拟业务或真实业务。通过一个层次不能替代其余层次。当前新微内核仅覆盖部分授权与上下文基础；S1–S10完整链尚未实现。

## 下一纵切顺序

先完成只面向模拟接收端的 Permit/单活动 slot/恢复协议，再把“合成感知→工作生物→受保护结构化场景提案→本地模拟校验→场景收起/恢复”接成同一可运行测试。随后分别替换真实感知、获准模型和 Flutter 呈现，保持相同系统契约。不得为展示速度先接真实开户或把模拟表单说成智能生成。
