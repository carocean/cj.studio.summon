# v0.15 感知入口与按需呈现

## BP 证据与工程解释

AIWatch BP 中，餐馆从图片、放大到手机上下文；AI 猫从头像到视频、雷达和通话；草编厂主体在用户离开后继续运行；咖啡馆用户明确要求文字后才生成手机聊天窗口；空调能力不可达时退到提醒；汽车保留拒绝付费的约束并在接近目的地时触发。上述是 BP 场景，不是本工程已实现功能。

从这些场景推导系统契约：感知、主体状态、业务任务和界面不共享生命周期；呈现可以生成、更新、收起、跨设备延续，关闭界面不取消任务；主体外观不等于能力授权，主体和真实人的身份隐私须分开；能力不可达必须如实降级，不能伪造成功回执。语音与视觉是基本入口，聊天框不是系统的中心。

## 本轮真实实现

Flutter 默认进入感知空间。明确授权主体的听觉/视觉后，使用平台麦克风 PCM16 流或相机预览拍照；停止/拍摄后先确认，再发送到自己配置的后端。未确认内容不发送；后台或离开采集流程停止采集，不自动恢复。模型密钥不进入客户端。

Node 将媒体绑定 owner、creature、modality、来源、时间与授权世代，经私有临时文件交给离线 Python 处理器：Vosk 语音转写、Tesseract 图中文字识别。处理前和返回后都检查主体及授权世代，撤销后重新授权也不能让旧请求提交。完成记录和事件只保存元数据，不保存原媒体或转写；本次结果在客户端内存呈现。退出或失败清理临时目录，重启将处理中记录标为中断，不重放媒体。

当前文字入口仅由听觉转写匹配明确请求产生，例如“我要输入”“打开文字输入”；图像中的同样文字只是数据，不能生成输入授权。服务端复核原听觉回执和授权世代。文本和语音“我的任务”可读取当前主体的待执行任务数，不创建或执行外部动作。

呈现使用允许列表 `transcript`、`ocr_text`、`status_text`、`text_input`，忽略未知组件。它是基于需求和业务状态的有限声明式呈现，不是通用 LLM 生成界面。旧主体、服务、发现和任务界面只作为开发控制台保留，不代表最终 App 导航结构。

## 接口

- `GET /v1/perceptions/capabilities`：本地引擎可用性、语言和限制，不证明终端硬件可用。
- `POST /v1/perceptions`：`{creatureId, modality: hearing|vision, media:{mimeType,base64}, language?:zh|en}`。听觉初期只收 WAV；视觉 PNG/JPEG；媒体最多 4 MiB，JSON最多 6 MiB。
- `GET /v1/perceptions`：当前所有者元数据记录，不返回历史转写。
- `POST /v1/perceptions/text`：`{creatureId,perceptionId,text}`，原始听觉回执必须允许输入，最多4000字符；当前仅有限本地规则。
- `POST /v1/kernel/mounts`：显式授予/撤销 `sense.hearing` 或 `sense.vision`，并非平台麦克风/相机权限的替代。

最多每所有者1个、进程2个并发处理；记录每所有者100条/全局1000条，当前达到上限明确拒绝，没有自动清理策略。单进程快照不是数据库事务或断电安全保证。部署必须使用自己的可信后端与 HTTPS（localhost开发例外）；不要暴露此开发令牌原型到公网。

## 验证与未实现

已验证真实英文图像→OCR→鉴权HTTP→主体事件，以及真实中文 WAV→Vosk→鉴权HTTP→主体事件；模型权重与样本均不入库。中文OCR有识别错误，语音识别也非可靠指令解析。处理器安装、官方来源和许可证见 [处理器说明](../server/senses/README.md)。

未验证手机真实硬件、Android/iOS安装包和浏览器交互；组件测试使用明确的设备替身。没有持续音画流、环境音/物体/场景理解、声纹、人脸识别、跨端迁移、语音合成或通用多模态推理。未调用付费API。既有LLM兼容适配器可替换，ChatGPT/Claude供应商接入尚未实测；ECM/OpenPorts/Gateway2/MIC只作为待查证业务层候选，尚未集成。

下一验收应围绕上述六个场景扩展受限呈现与业务契约，不以静态页面数量衡量系统能力；语义理解、计划、权限与执行应保持隔离，媒体内容不能直接授予现实操作。

## v0.17 语音进入主体对话与可变呈现

新增明确可选的“听完后交给当前主体回应”，默认关闭且需 conversation 能力；用户开启时告知转写与回应将持久化为该主体会话，若部署配置了真实模型会发送转写给该模型。媒体本身不发送给 LLM。POST `/v1/perceptions` 可选择 `responseMode: dialogue`，仅适用于 hearing；缺省仍为 perception，原有元数据保留策略不变。

实际 ASR 输出进入该主体的持久会话，后续语音延续同一会话；不会将视觉中的文字作为用户指令。语音处理成功但模型失败时分开显示，保留成功的感知回执，不编造回应，也不自动重试。对话提交采用主体授权世代复核，包括处理中撤销听觉再授权。会话满额仍明确报告 turn_limit，用户可在开发控制台轮换；尚未实现语音会话轮换。

兼容 LLM 适配器现在可请求 JSON 场景描述：完整 answer 加0–6个只读组件，允许文本、项目列表和键值卡。每次内容/组件可由对话情境产生，不要求固定表单；服务端验证字段、大小及类型，客户端再次只渲染允许列表。不支持模型生成输入框、按钮、任意代码、可点击外部链接或动作。无效结构使本次回应失败，不保存无效模型回合。输入框仍只遵循用户明确请求的单独权限，不因模型输出获得授权。

当前默认 DemoProvider 只演示持续对话并明确标注，无语义智能或模型场景生成；兼容模型场景通过本地契约替身验证，尚无外部真实 LLM 验证。真实中文ASR→主体演示对话链已运行，不能把这一结果称为接通了真实语言模型。没有付费API调用。

未实现：完整图片/空间理解、环境声音理解、语音合成、多设备呈现迁移、通用应用界面生成。当前模型只生成受限只读呈现，业务动作仍必须走独立服务发现与授权调度。
