# 按业务契约呈现受限表单

## 为什么做这一步

生物收到需求后，应按当前业务、权限及持久状态准备所需界面，而不是默认展示聊天框。原型中的账户表单已带字段声明，但 Flutter 仍重复写死三组选项；地图起终点也另写了一套组件。本轮将这两种已有合成服务接到统一 choice-form 契约。它是受限的契约驱动呈现，不是 LLM 任意生成界面、创建新服务或完整生成式操作系统。

## 层次与身份

- 服务定义拥有字段与允许值；渲染器不拥有服务权限。
- 声明绑定接收情境与目标生物，二者可不同。例如个人伙伴打开市场，为已订阅地图生物准备请求。
- 账户声明绑定已有任务及修订；路线声明绑定产品、订阅实例及授权修订/世代。路线输入尚未提交时只是当前快照，**不是新建的持久任务或租约**。
- formId 是服务版本、绑定与完整字段声明的摘要，包含顺序、标签、选项、只读状态及当前值。摘要用于绑定/冲突检查，不是签名或用户身份认证。
- 无 expiresAt 字段；有效性来自当前状态重新核对，不宣称时间租约。情境 ABA、任务替换或订阅撤权再授权会让旧绑定失效。

## 封闭声明

`choice-form.v1` 仅允许两个 contractId：`synthetic-account.v1`、`synthetic-route.v1`，contractVersion 为1。

声明包含 formId、binding 和 fields。binding 包含 context（creatureId、sceneRevision）、targetCreatureId、activityId/activityRevision、productId/instanceId、subscriptionRevision/subscriptionGeneration。该服务不用的字段明确为 null。

字段只支持 choice：id、纯文本 label、required、readOnly、options（value/label）、value。未知组件、重复字段/选项、非法当前值、超限内容及未知服务版本均拒绝整张表单，不跳过坏字段后继续执行。没有自由文本、敏感身份字段、脚本、任意 URL、外链、模型自报动作或组件下载。

账户仍仅有合成客户、模拟账户类别、模拟联系偏好；地图仍仅 A/B/C 合成节点。Flutter仍保留两个已注册契约的语义白名单（字段ID与最大允许值集），不是任意服务器schema即获信任。渲染顺序、标签、合法选项子集及当前值取声明；新增业务契约仍需审核和客户端策略更新。当前两个服务产生不同字段集合，任务状态决定只读；组件契约允许字段顺序、标签及合法选项变化，但当前运行时未开放任意配置或新服务注册。支持声明变化不等于证明任意模型生成的内容可被信任。

## 操作不是声明中的程序

- 固定 `/scene/form-update` 接收 formId/binding/values，仅保存合成账户草稿。
- 固定 `/scene/form-route` 接收 formId/binding/values/requestId，仅请求合成路线。
- 服务器从当前状态重新生成声明并比较绑定与摘要，再检查所有值、只读约束及既有服务授权。客户端提供的选项或标签不能改变服务规则。
- 账户真正模拟提交继续走既有 Grant/Context/Permit 链；路线继续使用既有一次性请求身份、取消、未知状态及回执。
- 展示、选择或保存草稿都不等于业务完成；只有校验通过的对应回执才能显示成功。
- 老接口为实验兼容保留，因此新绑定门只覆盖新的契约入口；不声称把所有旧调用都迁移为这一协议。

## 前端状态原则

共享渲染器只管理封闭字段和值，外层的受信业务控制器选择固定 API。相同表单身份刷新不应覆盖未保存草稿；绑定/声明变化不能把旧草稿悄悄提交给新任务或新授权。需重新核对后加载新声明。未知路线请求仍只能查询或取消，不自动生成新请求重派。

收起界面不销毁服务器任务和回执。视觉上隐藏不等于多 Agent 数据隔离；当前 loopback 演示 API 仍是一个合成 owner，没有生产用户认证。

## 验证限制

后端执行 Node/真实 loopback HTTP 测试。客户端最初因先前平台拒绝而只做静态审查；随后查明官方SDK的CI检测分支，在原沙箱声明CI、阻止不必要的metadata探测后恢复执行，并发现和修复终态仍显示提交按钮的回归。没有修改SDK或放宽网络安全限制，详见[本机验证记录](FLUTTER-LOCAL-VERIFICATION.md)。没有真机、真实银行、真实地图、付费供应商或通用自然语言规划验证。

后端本轮聚合：198项通过、6项真实依赖测试默认跳过。新增契约7项覆盖真实HTTP、重启、任务/情境/订阅ABA、声明和参数篡改；内部独立审查另跑相关25项及6组反例，未复现新增P1/P2。伪造者可以重新计算摘要，甚至让自造声明通过纯结构校验，但无法使宿主当前表单比较接受它。旧接口仍有旧行为，例如隐藏草稿可通过旧update接口在工作主体下保存，不能把新路径的保证套到旧路径。

Flutter共用渲染器、草稿与两个业务控制器的最终执行验证：静态分析无问题，149项组件测试通过、1项默认跳过；显式启用的实际Dart→Node HTTP新契约链1/1通过。不作手机可安装/发布版本承诺。

后端新增声明后，实际固定WAV→Paraformer→独立确认→合成路线回执→MeloTTS回归再次1/1通过（约12.9秒）。仍是同一合成声音素材，不是真人或手机采集证明。

修复后的Web release最终构建通过（61.5秒），客户端已不再停留在仅静态阶段。手机硬件、签名安装及公开部署仍未验证。
