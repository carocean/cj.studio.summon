# 产品基线 v0.2

## 原意已核实：AIOS 是 Calling Operating System

依据用户在 2025-01-16 提供的 AIWatch BP 原文，AIOS 的主线是“你呼唤，我服务；你提示，我服务”。它不以传统 App 为服务组织单位，而由 AI 理解呼唤，调用或生成服务。AI 服务是 AI 生物的能力，例如餐馆替身提供点餐。

本工程不能停在“带头像的模型聊天”。核心链条是：**感知/提示 → 理解意图 → 服务发现 → 能力与权限检查 → 调度执行 → 呈现结果 → 状态延续**。Flutter App 是第一种宿主界面，不意味着内部服务组织回退为 App 集合。

## AI 生物与 AIBM

原文列举 personality、activity space、service abilities、rendering abilities；这是当前 AIBM 字段的依据，不应冒称 BP 的完整形式定义。AI 生物还具有感官、听说和活动等构想；可以随设备移动或固定在餐馆、学校、树等地点。手机、PAD、PC 可协同辅助显示和输入，目标是延续同一主体而不是每个屏幕另建一个角色。

当前实现采用 AIBM 的一个工程化子集：人格描述、模拟活动空间、服务白名单、可呈现结果种类。人格不是权限，LLM 输出也不是授权。未来真实设备能力与空间证据必须来自经过认证的适配器，不能信任客户端自报 zone。

## 已实现的最小调度闭环

- 同一句“你能做什么”发给个人同行者或餐馆替身，经服务计划、边界检查和调度，返回各自主体真实注册的不同服务能力。
- 菜单读取与价格预览是确定性服务实现，但使用显式演示菜品，绝不连接真实商户、提交订单或付款。
- 会话只是 `conversation` 服务。餐馆没有该能力，不能绕过 AIBM 调用通用会话来冒充服务。
- 模型意图规划尚未实现，当前明确采用 `demo-rules` 规则；模糊或超出能力的提示要求澄清，计划不自动代表执行授权。
- 表情、动作、手势、真实定位、IoT、AR、跨屏接续、服务生成与服务训练尚未实现。

后续应以服务发现与调度、主体状态、真实边界、跨端呈现发展，不以聊天气泡数量衡量进展。
