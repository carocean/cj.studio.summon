# 菜品语义提案：系统级明确确认

## 实现边界

模型输出不是用户授权。`DishConfirmationHost`只接语义提案模式的真实`DishHearingTurn`实例，不能连接会自动执行的有限整句模式。模型/转写/网页文本不能注入按钮、确认字段、执行目标或系统文案。none/clarify/error转换成固定状态，模型生成的提问和原因不进入系统提示。

宿主专用`ingest`只接受原有音频契约，不接受文本资源或确认字段；返回的待确认呈现只包含schema、状态、随机交互ID、原事件到期时间和目录菜名。内部原提案、事件绑定与权限不传给客户端。用户通道`read/respond/invalidate`独立持有，`respond`只接受交互ID及show/dismiss，不接受客户端的proposal、stop、owner或菜品替换。

令牌在任何await之前单次消费；并发响应拒绝、重复点击旧ID返回expired，不重复动作。展示和确认时重新检查原场景、任务、菜、目录、revision、听觉授权代际及事件TTL。撤权再授予不能恢复旧提案。失败/失效时不给成功反馈、不规则降级、不重新授权、不自动播报。关闭失败后仍保持失效，但允许重试停止和退休。

这是进程内受信宿主能力分离，不是对同进程恶意代码的沙箱。网页、外部agent、模型工具与资源处理器不得持有用户通道；任何未来插件接入仍须建立独立信任边界。

## 受保护传输

`createProtectedPreview`可显式注入`dishConfirmation`宿主实例。未注入时新端点全部关闭。注入时只开放：

- POST `/scene/dish-confirmation-read`，body `{}`。
- POST `/scene/dish-confirmation-respond`，body `{interactionId,choice}`。
- POST `/scene/dish-confirmation-invalidate`，body `{}`。

三者直接调用受信用户通道，不转发到未认证loopback服务。沿用直接TLS、单用户会话cookie、同Origin、CSRF、内容类型和大小限制。启用该模式时禁用通用`dish-command`，防止调用details绕过确认。未开放创建提案、音频上传、宿主stop确认或模型调用端点。

会话注销、轮换、到期和preview关闭使当前确认宿主失效。失效宿主不自动复用；要恢复须由受信宿主创建新链，而非客户端再授予权限。读接口不会执行动作。错误响应不证明操作失败（网络可能在操作后断开），客户端不得盲重试。

仍是单用户受保护预览架构，不是多租户/生产级账号系统。持有同源会话和CSRF的受信用户通道有确认能力，不能将此凭据交给网页内容或外部agent；不能据此声称人类真实在场。

## 按需生成界面

Flutter契约严格解析固定字段，只有pending可带交互ID/到期/菜名。面板按需出现“要展开『菜名』的说明吗？”、“展开说明”、“不用了”，菜名仅纯文本。无默认输入框、无模型定义链接/按钮、不默认嵌入Home。

客户端到期、撤权、后台、替换、销毁会丢弃旧状态并尽力通知宿主；通知失败不恢复界面，也不声称宿主已成功停止。晚响应不能复活旧面板；提交期间禁双击。用户明确触摸/无障碍激活才发送选择，语音“好”、眨眼和自动脚本不作为另一个授权源。

此处只处理“展示绑定菜单中的菜品说明”，不授权点单、付款、订阅、分享或运行模型生成代码。其他业务须有独立协议。

## 验证真实性

本轮宿主与TLS集成使用真实SQLite状态机、真实临时TLS证书/请求和受控ASR/模型/播放器替身。Flutter widget测试模拟用户点击，不是真机触摸，也不是真实麦克风、扬声器、真实模型或全双工实验。测试证明相应软件边界，不证明感知或LLM质量。

V2语义质量候选没有被采用，仍保留原提示词及已知失败记录；安全确认降低错误模型输出直接变成动作的风险，不把模型判定变成可靠理解。

## Flutter与受保护链路

`DishConfirmationRemoteSurface`仅在宿主明确挂载时使用现有受保护API读取待确认，点击后提交一次选择。退出、初始无权限/后台及后续失效会尽力请求宿主退休；失败显示“尚未确认服务器撤销”，不声称已经安全停声。客户端与API的白名单只增加上述3个确认POST。

真实本地TLS的Flutter集成已验证：点击前SQLite菜品view为none；点击后同一菜、task、catalog进入details；只有一次响应请求且只含interactionId/choice，重放expired。使用临时证书显式信任，不关闭证书校验；测试凭据为临时合成预览邀请。

**客户端此组件只显示确认问题及成功/失败反馈，没有自动挂载菜品详情阅读组件。** 后端details状态通过受保护dish-read核验；不能把它称作已经完成的用户详情页，更不能称默认首页或真机运行。
