# AIOS 系统骨架与来源映射 v0.3

## 对原始 BP 的逐层理解

已研读 AIWatch BP v1.0 全部 14 页文字，并核对第 3、4、6、7、8 页图像。以下只写系统含义，未复制私人联系信息或整份 BP。

| 来源 | 原文内容 | 本工程推导，非 BP 已实现声明 |
|---|---|---|
| p1–2 | AI 生物代行；批评入口经济和有限 App 的服务发现方式 | 服务发现不依赖用户先知道 App 名；不能只做模型切换菜单 |
| p3 | AI instruction scheduling、AIBM、第三方服务训练、感知、AI Protocol；Android 底座、连接器、渲染与服务 | 调度内核、主体/服务模型、设备能力适配层、事件协议、呈现协议分开；当前服务端 Node 原型不是 Android OS 实现 |
| p4 | 不采用传统 App 架构而直接采用服务；AI 理解后调用或生成；服务属于 AI 生物 | 模型只提出调用计划，系统负责发现、边界、授权、执行、回执；生成的服务要检验，不能任意执行模型代码 |
| p5 | 手表前置摄像与多感官硬件设想 | 所有设备感知要有能力探测及授权，未实现的感官不能靠 UI 图标冒充 |

| p7 | 创建固定草编厂、挂载广播、规则限频、离开后继续、回报；咖啡馆跨端输入 | 持久主体、服务挂载、周期/事件任务、政策约束、回执、跨端会话。当地“一天一次”是故事中规则，不是现行法律事实 |
| p8 | 空调失去范围后不能远程关机，改提醒；车接近目的地再指导且不预约 | 连接可达性影响可执行能力；降级任务、持续约束、事件触发与恢复 |

| p10–14 | 生态、商业模型、团队、融资、联系 | 属于业务愿景，不直接决定内核语义或证明功能已实现 |

## 通用对象与边界

1. Subject：稳定身份、所有者、生命周期和 AIBM。不是一段 system prompt。
2. Service：声明输入/输出、效果、前提、版本、连接依赖；服务挂载不等于对一切请求的永久授权。
3. Intent/Plan：来自语言/感知的解释候选，不是执行许可。
4. Task：在授权与规则范围内保存未来工作，包含状态、约束、触发条件、取消与结果。
5. Event：来源、时间、主体、内容、可信度、关联上下文。模拟信号必须与真实设备证据分开。
6. Connector：当前可达性与可操作范围，不能把“有该工具”当成“现在能执行”。
7. Presentation：依据设备与 AIBM 呈现边界显示同一个服务状态，不复制主体身份。

AIBM 原图明确四项：Personality、Activity space、Service abilities、Rendering abilities。工程上的授权、资源配额、审计和密钥隔离是补充机制，不冒称原文完整定义。

## v0.3 实现边界

`Kernel` 已提供持久主体、挂载/撤销、暂停/退役、时间与事件任务、周期限频、取消和本地回执。数据用单进程 JSON 快照原子替换；服务进程每秒检查任务，不依赖 Flutter 页面开着。重启恢复后不补发累积周期，避免追赶式爆发。

唯一可挂载执行器 `local.report` 只产生本地回执，不发送广播、消息，不操作空调或车，也不付款。其任务执行与结果保存在同一快照。由此能验证生命周期，但不能宣称实现真实广播、IoT 或跨系统 exactly-once。

目前有两套明确分离的实验接口：v0.2 的静态主体/演示调度和 v0.3 的持久内核。尚未将持久主体接入 Flutter 和 LLM 规划，不能把二者描述为已整合产品。下一轮优先统一主体注册与服务模型，再逐项接入。

## 测试与生产差距

- AIBM 活动空间是模拟标签，未读取设备定位。
- 事件由本地 API 显式输入，不是可信传感器事件。
- `payload.constraints` 保留用户意图，但当前不支持付费/预约执行器，所以不构成通用策略语言实现。将来外部服务必须结构化执行约束，而不能仅把文本塞进提示词。
- 单一开发令牌映射一个所有者，不是用户注册或多租户权限系统。
- 每个数据文件只允许一个进程持有目录锁。异常崩溃可能遗留锁，必须核实旧进程结束后由运维恢复，不自动抢锁。
- 原子 rename 防止部分 JSON，但当前没有 fsync/数据库事务，不保证断电耐久性；没有分布式租约或多副本。
- 回执保留最近 1000 条、事件最近 2000 条；不是永久审计存档。
- 后台只在本地服务进程运行期间调度，不承诺电脑关闭或云容器停止时继续。重启可恢复数据但不代替部署。

## v0.4 统一状态与服务模型

生产入口现在让 Runtime、ServiceScheduler 与 Kernel 使用同一主体目录、挂载能力与持久会话。首次启动为该所有者种入三个模板主体，模板只是初始配置；之后暂停、撤权或退役不会在重启时自动恢复。新建主体也通过同一个 `/v1/creatures` 发现和 `/v1/invocations` 调用，不存在另一套只能聊天的生产主体注册表。

公共服务描述集中于 `model.js`；AIBM 服务能力来自持久挂载记录。挂载服务时把对应受支持的结果呈现类型加入该主体，撤销服务则同时取消相关未完成任务。当前持久任务仍只允许纯本地 `local.report`，不会因挂载 conversation 就自动允许后台花费模型调用。

会话保存在同一数据快照中。模型调用开始前检查主体及能力，返回后再次检查；期间暂停或撤权的结果不提交。校验不能撤回已经发给供应商的输入或已产生费用，后续可增加可取消请求。并发适配器使用会话长度版本检查避免覆盖较新的回合。

v0.3 数据加载时将字符串 activitySpace 转为模拟空间对象，并添加空 sessions；原主体/任务保留。迁移不是删除数据，快照下次成功写入时保存规范化形态。测试夹具保留可选无 Kernel 内存模式，只用于隔离测试，`main.js` 不使用它。

Flutter 客户端会读取新的统一主体列表，但尚未安装 SDK/编译；客户端还未实现自动恢复最近会话。后端有可恢复会话，不意味着手机重启后已自动续接。
