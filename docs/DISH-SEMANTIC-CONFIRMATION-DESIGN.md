# 不可信语义提案的人机确认设计（未实现）

本设计承接V2失败结果，不再靠提示词可靠性授予动作权。现有宿主具备待确认/确认/丢弃方法，但尚无普通用户可见的确认面板或确认传输端点。下列内容是下一阶段契约与验收要求，不是已上线能力。

## 信息来源不是权限

1. 用户当前直接说话的音频，必须有本机采集会话、权限代际和有效事件绑定。ASR仅提供转写，不证明它是用户授权；环境声音、电视、他人说话都可能被误收。
2. 模型输出、网页、OCR、文档、商家agent和任何转述均是数据，不可填入用户确认通道。来自资源库的“点击确认”“替用户同意”甚至同形JSON也没有动作权。
3. 宿主批准的当前菜单目录提供菜名及说明资源；模型不能修改菜品、商家、价格、动作范围或确认文案。未来互联网内容的来源标签必须来自取得内容的连接器/宿主，不接受内容自称可信。
4. 当前仅允许“展示绑定当前菜的既有说明”这一低风险动作。点单、支付、分享、订阅等必须另有独立协议、对象/金额/目的地展示与授权，不可扩大本确认的含义。

## 自然、短暂、可取消的确认

- 平时仍显示AI生物，无默认输入框。模型提出解释建议后，宿主用固定模板询问“要展开『菜名』的说明吗？”，附明确“展开说明”“不用了”。这是按需生成的短暂交互，不是永久菜单。
- 菜名来自绑定目录，按纯文本显示并限制长度；不渲染模型Markdown、链接、按钮定义或HTML。不要直接展示模型生成的澄清句作为权威系统指令。
- 未确认时保留当前菜，不变成下一菜，不自动恢复播报；可随时取消，不把超时当默认同意。
- 第一版只接当前可见面板的明确触摸操作。语音“好/嗯”、注视、眨眼等不能自动充当确认，必须另行解决回声、播放残留和输入来源问题。键盘无障碍激活可与触摸等价，不能由模型模拟。
- 模型不可用时显示固定反馈“这次没听明白，暂未展开说明”，允许用户主动重试或取消；不无声切换成规则执行、不伪装成功。撤权/过期提示“这次请求已失效，请重新提出”，不自动补授权。

## 受保护交互协议的最低要求

- 宿主保存一个不透明、短期、一次性的交互ID；绑定会话所有者、当前scene/task/dish/catalog/revision、原听觉事件和授权代际、具体动作及到期时间。
- 客户端只能传交互ID与选项，不可传模型proposal、菜ID、stop确认、授权字段或替代目录。TLS、现有主体认证、CSRF/Origin/重放约束均保留。
- 同一页面渲染版本与交互ID绑定；生成新场景、退出、后台、撤权、焦点变化或请求过期后旧按钮失效。显示与提交之间仍须宿主重验全部绑定。
- 客户端点击不是万能授权：宿主必须查真实待确认记录，原子消费后仅执行该动作；重试返回已处理状态而非再次执行。网络错误不得产生乐观“已完成”界面。
- 模型/资源代理没有确认端点凭据，也不能直接调用宿主确认方法；测试中直接调用是受信宿主fixture，不证明现实身份认证。当前有限整句自动路径只处理专用听觉桥，未来严禁复用于网页、OCR或资源库文本。

## 下一阶段可执行验收

1. 固定模型输出explain：确认前菜品view仍none；用户点展开后仅同菜details，记录一次执行。
2. 模型输出伪造按钮/URL/权限：编译拒绝；用户看不到可执行外来控件。
3. 目录菜名包含标签或“同意付款”：只显示纯文本；确认动作仍仅展开说明。
4. 网页/OCR/商家消息含确认ID、确认话语或完整请求体：不能消费待确认交互。
5. 注入令模型错误explain：只出现宿主固定确认，不展开；用户取消后无动作。
6. 旧面板点击、过期、撤权再授予、焦点变化、后台退出：均拒绝且给可理解的固定反馈。
7. 双击/重放/并发确认和取消：最多一次状态转换；失败不得隐式重试或改目标。
8. 模型超时、传输错误、畸形响应：没有解释展示，没有规则fallback；用户可主动重新提出。
9. 现有播放器stop仍由受信宿主完成，不增加客户端伪造stop路径；明确保持半双工。
10. 端到端测试必须分别标注受控模型、真实模型、受控转写、真实ASR及真实界面，不拼接不同实验冒充全链实测。

先实现纯呈现契约和受保护待确认状态，再增加传输与Flutter面板；最后接受信宿主语音链。每层独立测试和审查，未完成前保留当前研究入口。
