# 第三个受信业务：本机合成专注计划

## 验证目标，不是另堆一个 App

账户保存、地图路线之后，第三种业务用于验证同一受限声明能生成不同服务所需的表单，而不修改通用 Flutter 渲染器。先独立抽离业务策略并验证既有两服务，再增加新服务策略与控制器。阶段A基线提交为 `da4b87bf1eb64c13638e677d0b0abb2ee1a903ba`；通用模块及类段摘要见 `choice-renderer-baseline.json`。

这只证明**第三个编译期受信业务可复用声明机制**。仍需服务实现、受信策略和固定业务控制器，不是任意第三方安装、模型生成代码、LLM通用生成或完整平台生态。新业务从主生物的按需入口准备，不新增固定Tab或默认文本框；当前没有给它接自由语音理解，不把按钮入口冒称自然语言已经贯通。

## 服务与安全域

`synthetic.focus.v1` 创建本机合成计划记录。三个字段：topic（学习/整理/写作）、duration（5/15/25分钟）、pace（稳定/温和）。pace 仅保存偏好，不控制用户、屏蔽应用、安排分段提醒或发出通知。无外网、收费、真实预约或设备控制。

新安全域是**owner自己的持久计划与时间状态**，不是跨生物委托。每owner至多一项active计划，防更换主生物绕开已有计划；请求账本每owner最多128项，不共用跨owner配额。没有自动循环、后台提醒进程或跨设备保证。

## 主生物不等于管理员

- 只有当前主生物正在前台时才能准备新计划。
- 每个owner/creature的服务许可独立，默认false；听觉、视觉、种类、个性或primary身份都不授予专注服务权限。
- 用户明确允许后才生成可提交表单；授权不是从模型或声明中取得。
- 表单绑定当前具体creatureId、registryRevision和grant revision/generation。注册关系版本是保守边界，不仅主关系变化，其他注册变化也可能使旧表单失效。
- A→B→A不让A的旧表单复活；A此前独立许可可以仍存在，新声明必须重新取当前绑定。
- 改主生物不迁移、取消或重建旧计划。原实例身份与历史保持，owner仍可查询和取消；这不赋予新主生物无限跨主体能力。

## 创建、查询、取消的事实

创建在同一单写事务中保存固定请求身份、原实例、输入、创建时间、期限和创建回执。回执的 `fact:plan_saved` 只证明记录已保存，不证明用户已经专注、完成了事情或收到通知。

计划状态是 active/elapsed/cancelled。查询观察到期限到达时持久锁存elapsed；后续时钟回拨和重启不能复活这个已观察状态。它只表示时间已到，不是用户完成；无法证明未观察到的离线时钟回拨，不能宣称严格单调时钟。创建失败不能回滚之前独立锁存的到期事实。

请求状态与计划状态分开：成功创建的请求保持completed，即使其计划后来取消；原创建回执不抹除。未创建的requestId可以明确取消并写墓碑，防迟到创建；满额不能伪称取消成功。没有客户端未知重派。

关闭界面不删除记录；程序重启后按保存期限查询。这里的“继续”是持久状态和期限，不是声称程序关闭后仍有后台任务替用户做事。

## 契约与恢复

`synthetic-focus.v1` 使用 choice-form.v1，binding严格为 context、targetCreatureId、registryRevision、grantRevision、grantGeneration、serviceId。formId覆盖完整声明；不是签名、不是TTL租约。

固定入口：focus-grant修改当前主生物的独立服务许可；form-focus明确创建；focus-cancel取消请求/计划。state用于恢复持久请求和回执。新建表单入口重新核对当前表单，不保证旧表单历史重放；底层服务对相同请求身份与输入可返回既有事实，不再执行。用户看到结果未知时只能核对或取消，不能以新ID自动重派。

当前HTTP仍为loopback单演示owner；底层身份句柄隔离测试不等于上线多用户认证。旧账户/地图接口保持其原边界，不因新增专注服务获得额外保证。
