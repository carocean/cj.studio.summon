# cj.studio.summon · 唤起

**当前主线：** 生成式操作系统的入口是 AI 生物，而不是应用目录、固定服务菜单或聊天框。Flutter 首页在空历史时只显示有眼耳的替身动画，没有默认文本框、功能菜单或隐藏点击区；业务/输入界面仅按需呈现，旧功能留在独立开发工作台。当前仍是单机 Node.js 微内核与有限确定性原型，尚无通用模型理解、视频语义或默认持续感知。互联网和各模型作为未来可组合的资源，不等于现在已接通。见 [最新产品纠正与下一切片](docs/GENERATIVE-EXPERIENCE.md)、[运行说明](runtime/README.md) 与 [子项目职责](docs/PROJECT-LAYOUT.md)。先单机跑通，不提前拆微服务或依赖ECM。

新增临时双向字幕：实际感知回包绑定当前生物与情境后可显示短字幕，生物字幕和嘴部说话动画由播放器真实状态回调驱动，不把“调用播放”当“已经说出”。默认仍无文字框/聊天列表；当前未验收手机持续采集/实际扬声，[常用小排](docs/REAL-USAGE-HISTORY.md)只显示本机宿主记录的实际重复操作，空历史不填占位。见 [最新交互要求与边界](docs/GENERATIVE-EXPERIENCE.md)。

新增受限实测：真实本地中文 ASR → 当前生物绑定 → 有限语音路线候选 → 独立确认 → 模拟地图回执 → 按需场景与显式离线朗读。仅指定提供者和合成地点，不是通用 LLM 或真实导航。见 [有限语音闭环与实测边界](docs/FINITE-SPOKEN-ROUTE.md)。

新增受限表单契约：账户、地图与本机专注计划共用 choice-form 声明，绑定任务/情境/订阅版本，后端重新核验。当前仅三个内置合成服务，不是任意界面生成；已在核实官方CI模式后恢复客户端执行验证，详细结果与边界见文档。见 [契约与验证限制](docs/CHOICE-FORM-CONTRACT.md)。

新增按需文字入口：对生物说“打开文字输入”并确认后才出现输入，或经独立开发工作台调用；输入“模拟开户”等有限口令后切换情境并生成合成表单。原文不保存、不送模型，默认仍不是聊天框。真实本机 ASR → HTTP → 声明 → 表单已实测；不代表手机录音或自由语言理解。见 [按需输入与证据边界](docs/ON-DEMAND-TEXT.md)。

新增按名字呼唤：有限整句“请切换到〈注册名称〉”提出精确目标，用户确认后切换前台生物；重名或不存在不猜选，不改变主生物或扩展听视觉权限。真实两段合成音频中一段识别错误被拒，一段准确完成闭环。见 [协议和完整实测边界](docs/SPOKEN-CREATURE.md)。

新增本机主生物委托：显式授权冻结的合成草稿，由工作生物生成受限产物并送回原主生物，具备中断恢复和真实本地接收回执。不是智能审单、外部银行或远程代理沙箱。见 [授权及恢复边界](docs/PRIMARY-DRAFT-HANDOFF.md)。

以下原server能力为保留实验与历史验证，不自动获得新微内核保证。

历史 v0.15 的默认入口已转为听觉与视觉感知空间，不再默认显示聊天输入。真实离线语音转写和 OCR 已贯通后端；手机硬件尚未实测，动态呈现目前是有限规则而非通用界面生成。见 [感知架构、接口与边界](docs/PERCEPTION.md)。旧页面保留为开发控制台。

独立的 AI 主体与能力运行系统，Flutter 客户端，服务端连接可替换 LLM。

**以下是历史 v0.14.0 server 原型记录，不代表当前整套运行时版本。** 后端的主体选择 → 复用/恢复会话 → 调用 → 返回结果闭环已通过本地 HTTP 测试。Flutter 已通过静态分析、32 项客户端测试与 Web release 编译，并完成 Dart 客户端到本地后端的真实 HTTP 联调；Android/iOS 原生包与真实 LLM 尚未验证。

## 产品主线

用户面对的是可识别、可持续交互的 AI 主体，而非只选择一个模型。模型是主体可使用的生成引擎；能力、权限、会话、状态与将来的空间关系由运行系统管理。现有 `/v1/discovery` 可在不预选主体的情况下发现当前所有者的服务，检查模拟空间及呈现边界，多匹配要求选择而不自动执行。Flutter 已有独立“全局呼唤”入口：不预选主体即可发现、明确选择并调用受支持的只读/本地服务，原会话与草稿保持隔离。现有调度器开放对话、真实能力自述、演示菜单和点餐预览，不允许模型直接执行现实动作。

这是一项依据 [GeoChat BP](https://github.com/carocean/cj.studio.geochat.bp/blob/main/BP.md) 启动的新工程。已进一步核实独立 AIWatch BP：AIOS 是 Calling Operating System，直接以 AI 服务而非传统 App 组织能力；服务属于 AI 生物，按呼唤理解、发现和调度。当前工程按两份 BP 与后续用户澄清，将地理连接、AI 生物和按需生成整合为同一系统，不把它们实现为三套产品，也不等同对话界面。来源、工程解释与实现范围见 [产品基线](docs/PRODUCT.md)。

## 子项目

- `microkernel/`：独立授权、来源、持久版本、Permit与受控模拟效果内核。
- `runtime/`：Node.js生物/情境/场景与任务编排、loopback HTTP适配，调用内核。

- `server/`：主体运行时、会话、调用入口和模型适配器。首轮采用无第三方运行依赖的 Node.js，便于验证协议与闭环；不是对长期后端架构的锁定。
- `app/`：Flutter 客户端源码，主体列表、唤起、会话视图和明确的演示模式。
- `docs/`：产品基线、接口和验证记录。

## 保留的 server 实验运行

当前主线微内核运行时需要 Node.js 24.22.1+（24 系列），启动步骤见 [runtime/README.md](runtime/README.md)。以下是独立旧 server 的启动方式，需要 Node.js 22+：

```sh
cd server
npm test
export APP_TOKEN="$(openssl rand -hex 24)"
npm start
```

请自行保存该开发令牌并在客户端输入。服务默认只监听 `127.0.0.1:8080`，不暴露公网。无 LLM 密钥时默认 `demo`，回复始终标明“演示模式”。

真实模型配置预留为 `LLM_MODE=llm`、`LLM_ENDPOINT`、`LLM_MODEL`、`LLM_API_KEY`，仅在服务端提供。接口使用 Chat Completions 兼容结构，已通过注入契约测试及真实 HTTPS 到本地兼容 Mock 的联调，但没有外部供应商或真实模型验证。不得把密钥放入移动端、聊天或仓库。

Flutter 3.50+ / Dart 3.14+ 准备后，在 `app/` 执行 `flutter pub get`、`flutter analyze`、`flutter test`、`flutter build web --release`。平台外壳、锁文件与测试已纳入仓库。网页开发需要后端明确设置本地 CORS origin，步骤见 [客户端说明](app/README.md)。原生 Android/iOS 未构建或签名，不应称为可安装手机 App。不要直接把此原型开放到公网。

## 保留 server 实验的边界

- 单一开发账号令牌，不是多用户认证系统；领域层有会话所有者隔离。
- 生产入口的主体、服务挂载、任务、本地回执及对话会话统一保存在持久内核；Flutter 已支持恢复最近会话，真实 LLM 尚未联调。
- 空间模式只是主体元数据，没有读取真实定位、地图/AR 或实际跟随能力。
- 没有工具执行、支付、外部消息或设备控制。
- 模型请求有超时与输出检查；尚无生产限流、账单预算、上游响应字节限制和审计系统。
- “AI 生物”是产品称谓，不代表已证实意识、生命或自显场。

下一步及已验证事项见 [STATE](docs/STATE.md)。

## 持续生命周期内核

当前新增持久主体、服务挂载/撤销、暂停/退役、周期/事件任务与本地回执。服务进程保持运行时，即使客户端断开也会调度；重启可恢复任务。仅运行本地回执服务，不操作真实设备或外部平台。[系统理解、来源映射与限制](docs/OS-ARCHITECTURE.md)。

`KERNEL_STORE` 可指定数据文件路径，默认从 server 工作目录写入 `../data/kernel.json`。不要把该目录提交仓库。不要同时启动两个写同一文件的进程。

当前生产服务使用统一持久主体目录：首次启动自动种入三个模板主体，之后用户创建的主体也出现在客户端列表中；重启不会重新授予已经撤销的能力。会话 API 支持按 ID 恢复消息，客户端已支持恢复最近会话。

精确构建版本、Mock 与真实接口的区别见 [验证记录](docs/VALIDATION.md)。

## 全局呼唤（v0.8）

连接开发服务后，点击顶部“全局呼唤”图标。输入“你能做什么”或“菜单”，选择明确标注的模拟空间，点击“发现服务（不执行）”。即使只有一个候选，也需先点选候选，再点“明确调用所选服务”。菜单用餐馆模拟空间；日常空间下不会假装餐馆可达。

当前界面只支持能力自述、演示菜单和本地回执的呈现/调用；不自动执行 conversation、下单或付款。修改提示或空间会废弃旧候选；调用失败会清空成功回执并要求重新发现。返回聊天不改变已选主体、会话或未发送草稿。

## 主体装配与会话历史（v0.9）

- 顶部“主体与服务装配”：创建无服务的持久主体，指定个性和模拟活动模式；明确挂载能力自述/本地回执，暂停或恢复主体。撤销服务前显示其会取消相关未完成任务的确认；不提供永久退役或任意外部能力装配。返回后刷新主体目录与能力。
- 已选可对话主体的“会话与历史”：查看旧会话，明确新建独立会话。满 50 回合不会自动清空或无限重试；旧历史保留，草稿按主体及会话隔离。新建仍受总容量限制，不能靠轮换绕过全局配额。
- 模型调用现在传入 AIBM 个性偏好；它只影响表达，不授予工具执行权限。调用途中撤权再授权、暂停再恢复，也会因持久授权世代改变拒绝旧结果提交。已发送给供应商的数据或费用无法因此撤回。

## 模拟连接可达性（v0.10，API 系统增量）

服务 `device.preview` 要求有时效的模拟设备连接。缺少连接、明确断开或租期过期时，发现显示不可用，调用也拒绝；重启不会自动续期。成功仅是本地预检回执，始终 `deviceActionExecuted:false`，不会控制空调或其他设备。Flutter 暂未提供连接器管理/预检入口，前台版本保持 v0.9。

## 失联事件与安全降级（v0.11，仍为本地模拟）

模拟连接断开/过期会记录一次持久 connector.lost 事件，唤醒事先明确安排的 local.report 事件任务。没有预设任务就只记录失联，不自行创建提醒；任务回执不等于通知用户或控制设备。反复读取、服务重启不会重复执行，重复任务仍受限频约束。

已被系统观察到的过期会持久锁存，之后墙钟回拨或重启也不会使旧租约复活；只有新的明确模拟连接上报能重新获得租期。未被任何运行过程观察到的时间流逝/回拨仍不能可靠推断，不能把此原型称为完整单调时钟或真实设备租约系统。

## 安全重试（v0.12）

主体创建、任务安排支持可选 requestId：同一所有者对同一请求重试时复用已保存的结果，服务重启后也不重复创建；换参数重用标识会被拒绝。Flutter 在创建响应丢失后先刷新核对，保持原请求标识再重试。重复响应带 replayed=true，只是原始成功回执，当前主体/任务状态仍要刷新确认，绝不重新启动已取消任务。

客户端请求标识仅在当前创建页面内保留，关闭页面或重启 App 不会自动恢复未确认请求。服务端记录最多 1000 条，不静默淘汰；达到上限时新带标识请求拒绝，已有重试仍可返回。该能力只覆盖本地创建/安排，不代表外部动作或模型调用的 exactly-once。

## 请求账本隔离加固（v0.13）

请求账本默认每个 owner 最多 100 条，同时保留全局 1000 条硬上限。达到个人配额时，已有请求仍可重试，不会删除记录；另一 owner 可使用剩余全局空间。内核状态只返回本 owner 的 used/limit，不暴露其他人的账本。

这是账本的前向隔离加固，不是完整多租户保证：已有全局满额记录不会自动清理，主体/任务/会话等仍有共享容量，多个 owner 仍可能共同耗尽全局预算。当前仍是单开发令牌，不应直接当作公网多租户服务。

## 持续任务与回执入口（v0.14）

在“主体与服务装配”中选择已挂载本地回执的活跃主体，进入“持续任务与回执”。可明确安排一次性延时任务，或等待一次模拟连接失联；刷新查看任务状态与本地回执，取消前需确认。离开页面不取消任务，后台仍依赖服务进程运行。

延时用服务端时钟计算，1 秒至 24 小时；同一请求重试不会把到期时间往后推。任务仅执行 local.report，不发通知、不广播、不控制设备、不调用模型。失联任务没有连接报告时可能一直等待；本页不会自动建立连接或制造事件。

## 可选 ECM 只读协议桥（v0.16）

已验证真实 AIOS 鉴权 HTTP→OpenPorts Hello，只读固定端点、gzip解压与双层JSON、授权世代复核；不代表菜单业务或集群集成。默认禁用、无自动能力授予，详见 [ECM-BRIDGE](docs/ECM-BRIDGE.md)。感知入口仍是主线。
